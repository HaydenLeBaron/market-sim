### 2.1. **Agents**

**Intuitively**: An agent is a economic "person" in the world that will:
- gather commodities
- consume commodities to survive
- trade surplus commodities on the open market

**Formally**:
```lean
namespace Agent
  structure T where 

    /-- a unique identifier for the agent -/
    uuid : String

    /-- the unchanging nature of the agent, which determines its preferences and constraints -/
    nature : Nature

    /-- the changing state of the agent, which is affected by its actions and the environment -/
    state : State

    /-- the agent's current inventory of commodities -/
    holdings : Bundle.T

    /-- per-tick in-kind income (representing commodities gathered/mined) -/
    endowment : Bundle.T

    /-- the speed at which the agent can trade. -/ 
    trade_speed : ℝ /- Will be useful for resolving priority in quantized time interactions (multiple agents may want to execute a trade on the same tick) -/
end Agent
```

An Agent has an immutable nature and a "mutable" (functionally updated) state:

```lean
import Mathlib.Data.NNReal.Basic -- for ℝ≥0

namespace Agent

  structure Nature where

    /-- The agent's simple love of the Influence Commodity-/
    influenceLove : {r : ℝ≥0} -- must be strictly positive to satisfy Non-Satiation axiom.

    /-- The agent's simple love of the Mithril Commodity -/
    mithrilLove : {r : ℝ≥0}  -- must be strictly positive to satisfy Non-Satiation axiom.

    For now `influenceLove` and `mithrilLove` act as simplistic biases for modeling static (if arbitrary) preferences for certain commodities.
    -/

    -/
```

We saw earlier that `Agent.T`s recieve/collect `Agent.T.endowment`s (income) as well as hold `Agent.T.holdings` (wealth). These are both `Bundle`s, which are an important concept in Microeconomics, as we will see later. They are defined as follows:
```lean
import Mathlib.Data.NNReal.Basic -- for ℝ≥0
namespace Commodity

  /-- You cannot have negative of something -/
  def Quantity := ℝ≥0

  /-- A Bundle is a quantity of a commodity. -/
  def Bundle := Commodity.T → Quantity
  /-
  NOTES: 
  We describe it as a function from a commodity to a quantity instead of a simple tuple to make it easier to write proofs about
  -/

  /-
  Bundles can be added and subtracted element-wise
  -/
  def Bundle.add (b1 b2 : Bundle) : Bundle := fun c => b1 c + b2 c
  def Bundle.sub (b1 b2 : Bundle) : Bundle := fun c => b1 c - b2 c
end Commodity
```

### 2.3. Commodity **Markets**: Continuous Double Auctions (CDAs)

#### Combinatorics of Bartering vs Monetary Economies

In a bartering economy with $N$ goods, there are $\binom{N}{2} = N(N-1)/2$ trading pairs and therefore that many markets. In contrast, if we choose one good arbitrarily to be a numeraire (unit of account) and treat it as money, then there are only $N-1$ markets. Therefore we see that monetary economies solve the problem of *double coincidence of wants* and the related problem of *combinatorial explosion of trading pairs*.

Another elegant property of choosing a numeraire is that it still encodes the relative bartering value of all other goods by dividing their "prices"–their bartering value against the numeraire, like so:

```lean
namespace Commodity
  /-- The price of a commodity in terms of a numeraire.
      This is the "bartering value" of the commodity against the numeraire. -/
  def priceIn (numeraire : T) (c : T) : ℝ≥0 := sorry -- determined by market (CDA)

  /-- The relative bartering value of commodity `i` in terms of commodity `j`,
      derived purely from their prices in the common numeraire.

      Key insight: if 1 Manna costs 3 Mithril and 1 Wood costs 1.5 Mithril,
      then the barter rate of Manna in terms of Wood is 3 / 1.5 = 2,
      i.e., 1 Manna is worth 2 Wood.

      This works for ANY choice of numeraire–the numeraire cancels out:
        (price_i / numeraire) / (price_j / numeraire) = price_i / price_j
  -/
  def barterRate (numeraire : T) (i j : T) : ℝ≥0 :=
    priceIn numeraire i / priceIn numeraire j

  -- Example with Mithril as numeraire:
  --   priceIn .Mithril .Manna     = 3.0   -- "1 Manna costs 3 Mithril"
  --   priceIn .Mithril .Wood      = 1.5   -- "1 Wood costs 1.5 Mithril"
  --   priceIn .Mithril .Influence = 10.0  -- "1 Influence costs 10 Mithril"
  --   priceIn .Mithril .Mithril   = 1.0   -- "the numeraire prices itself at 1"
  --
  --   barterRate .Mithril .Manna .Wood          = 3.0 / 1.5  = 2.0
  --     ↳ "1 Manna is worth 2 Wood"
  --   barterRate .Mithril .Influence .Manna     = 10.0 / 3.0 ≈ 3.33
  --     ↳ "1 Influence is worth ~3.33 Manna"
  --
  -- Thus N-1 prices (in the numeraire) encode all N(N-1)/2 barter exchange rates.
end Commodity
```
